# Elysia i18n 插件

`@pika/elysia-plugins` 的 `createElysiaI18n` 提供请求级语言协商、类型化翻译 key、变量插值和延迟翻译消息解析。

插件实现通用 i18n 机制，不依赖任何 `apps/*` 业务字典或错误类型。**字典按模块（module）组织**：调用方可以同时挂载多个业务模块的 zh/en 字典，TS 自动推导 `${Module}.${Key}` 形式的字面量联合，键入 `t('` 即可在 IDE 中看到所有可用 key。

## 一、创建实例

```ts
import { createElysiaI18n, type I18nLocaleMessages } from '@pika/elysia-plugins'

const commonZh = {
  FORBIDDEN: '禁止访问',
  VALIDATE_NUM: '长度在 {min} 到 {max} 之间',
} as const

const commonEn = {
  FORBIDDEN: 'Forbidden',
  VALIDATE_NUM: 'Length must be between {min} and {max}',
} satisfies I18nLocaleMessages<typeof commonZh>

const systemZh = {
  USER_NOT_FOUND: '用户不存在',
} as const

const systemEn = {
  USER_NOT_FOUND: 'User not found',
} satisfies I18nLocaleMessages<typeof systemZh>

export const i18n = createElysiaI18n({
  defaultLocale: 'zh',
  messages: {
    COMMON: { zh: commonZh, en: commonEn },
    SYSTEM: { zh: systemZh, en: systemEn },
  },
})

export const { t } = i18n
```

`messages` 的 key 为模块名（推荐全大写），value 为 `locale -> dict`。默认语言字典决定可用 key 和变量参数类型；其他语言通过 `I18nLocaleMessages` 检查 key 完整性。

## 二、返回 API

`createElysiaI18n` 返回：

- `plugin`：注入请求级 i18n context 的 Elysia 插件。
- `t(key, params?)`：生成延迟翻译消息，key 形如 `MODULE.SUBKEY`。
- `detectLocale(acceptLanguage)`：解析请求语言。
- `translate(locale, key, params?)`：按指定语言立即翻译。
- `translateMessage(message, acceptLanguage)`：解析延迟消息并按请求语言翻译。

## 三、注册插件

```ts
const app = new Elysia().use(i18n.plugin)
```

插件向请求 context 注入：

```ts
{
  i18n: {
    locale,
    translate,
  },
}
```

路由可以执行即时翻译：

```ts
new Elysia().use(i18n.plugin).get('/', ({ i18n }) => ({
  message: i18n.translate('COMMON.VALIDATE_NUM', { min: 6, max: 12 }),
}))
```

插件同时设置：

```http
Content-Language: en
Vary: Accept-Language
```

## 四、语言协商

`detectLocale` 按以下顺序处理 `Accept-Language`：

1. 解析语言列表和 `q` 权重，包括表示不可接受的 `q=0` 范围；非法权重会被忽略。
2. 按正权重从高到低尝试语言，权重相同时保持请求头中的原顺序。
3. 优先精确匹配已配置语言（合并所有模块支持的语言）。
4. 地区语言逐级降级，例如 `en-US` 匹配 `en`。
5. 基础语言可以匹配已配置地区语言。
6. 更具体的 `q=0` 范围会排除较宽泛候选，例如 `zh;q=0,*;q=1` 不会回退到 `zh`。
7. `*` 优先使用未被排除的 `defaultLocale`，否则使用首个未被排除的已配置语言。
8. 请求头缺失、非法、无匹配语言或所有语言均不可接受时使用 `defaultLocale`。

每次请求独立计算 locale，不修改全局语言状态。

## 五、变量参数

默认字典使用 `{name}` 声明变量：

```ts
VALIDATE_NUM: '长度在 {min} 到 {max} 之间'
```

插件通过模板字面量类型从 key 链路上对应的默认语言文案中提取 `min` 和 `max`，生成必填 params：

```ts
t('COMMON.VALIDATE_NUM', { min: 6, max: 12 })
i18n.translate('en', 'COMMON.VALIDATE_NUM', { min: 6, max: 12 })
```

参数值只支持字符串和有限数字。运行时使用 `{name}` 替换所有同名占位符；没有对应参数的占位符保持原样。

`t`、`translate` 和请求级 `i18n.translate` 收到非法参数时抛出 `TypeError`。`translateMessage` 解析到非法 params 时返回 `undefined`，由调用方决定回退行为。

其他语言应使用与默认语言相同的占位符名称。`I18nLocaleMessages` 只检查 key，不检查翻译文案中的占位符一致性。

## 六、延迟翻译协议

`t` 将 `${Module}.${Key}` 和可选 params 编码为带前缀的 JSON：

```text
i18n:{"key":"SYSTEM.USER_NOT_FOUND"}
i18n:{"key":"COMMON.VALIDATE_NUM","params":{"min":6,"max":12}}
```

`translateMessage` 执行：

1. 检查 `i18n:` 前缀。
2. 解析 JSON payload。
3. 校验 payload 为对象且 `${Module}.${Key}` 存在于默认字典。
4. 校验 params 为字符串或有限数字组成的对象。
5. 根据 `Accept-Language` 选择 locale。
6. 通过 `${Module}.${Key}` 拆分为 `module` 和 `subKey`，按模块路由到对应字典获取文案，并执行变量替换。

普通字符串、非法 JSON、未知 key 或非法 params 返回 `undefined`，由调用方决定兼容或回退行为。

## 七、类型

公开类型：

- `I18nDictionary`
- `I18nLocaleMessages<TMessages>`
- `I18nParamValue`
- `I18nParams`
- `I18nToken`
- `I18nModule`（`locale -> dict`）
- `I18nMessagesByModule<TModule>`（`module -> TModule`）
- `CreateElysiaI18nOptions<TModules, TDefaultLocale>`
- `TranslateMessageFn`、`TranslateMessageResult`

默认字典文案必须保留字面量类型，因此应使用 `as const`。否则变量占位符会被扩宽为普通 `string`，无法生成 params 类型。

## 八、安全边界

- JSON payload 只接受对象，不接受数组、`null` 或其他原始值。
- key 必须是 `MODULE.SUBKEY` 形式，且 `SUBKEY` 必须存在于默认语言下对应模块的字典中。
- 延迟消息中的 params 不接受嵌套对象、数组、布尔值、`null`、`NaN` 或无穷数。
- 插值结果只作为普通字符串返回；调用方负责根据输出位置处理 HTML 等上下文转义。
- 插件不读取用户、数据库或 app 配置，不负责 `HttpError`、Zod 或业务错误响应。

## 九、测试

测试至少覆盖：

1. 无参数和带参数 marker。
2. 参数类型推导（占位符缺省 / 多余 / 非法值类型 / 未知模块或子 key）。
3. 变量插值和重复占位符。
4. `Accept-Language` 权重、`q=0` 排除规则、地区降级和默认回退。
5. 普通字符串、非法 JSON、未知 key / 模块 和非法 params。
6. 多模块下同名 key 路由到不同字典。
7. `Content-Language` 与 `Vary` 响应头。
