# Server i18n 使用规范

## 设计目标

- **插件与数据分离**：`createElysiaI18n` 工厂位于 `@pika/elysia-plugins`，字典数据按模块存放在各自的 `locales/` 目录。
- **多模块支持**：每个业务模块自带 `locales/zh.ts` + `locales/en.ts`，运行时拼装到全局实例；TS 自动提示形如 `t('COMMON.FORBIDDEN')` / `t('SYSTEM.USER_NOT_FOUND')`。
- **共享字典自动包含**：任何模块都能调用 `t('COMMON.*')`；新增模块时先在 `common/plugins/i18n.ts` 注册，再在模块下加字典即可。

## 注册与定义

### 插件注册

全局实例位于 `apps/server/common/plugins/i18n.ts`，由 `src/app.ts` 启动时 `.use(i18nPlugin)` 挂载一次：

```ts
// apps/server/common/plugins/i18n.ts
import { createElysiaI18n } from '@pika/elysia-plugins'
import { commonLocales } from '@/common/locales'
import { systemLocales } from '@/system/locales'
import { demoLocales } from '@/demo/locales'

export const i18n = createElysiaI18n({
  defaultLocale: 'zh',
  messages: {
    COMMON: commonLocales, // 来自 common/locales/index.ts
    SYSTEM: systemLocales, // 来自 src/system/locales/index.ts
    DEMO: demoLocales, // 来自 src/demo/locales/index.ts
    // 按需添加模块...
  },
})

export const { i18nPlugin, t, translateMessage } = i18n
```

### 字典位置与新增 key

每个模块自带字典，**业务 key 加在所属模块**：

```text
src/<moduleName>/locales/
  index.ts  # 仅 import { zh } / { en } 后 export const <moduleName>Locales = { zh, en }
  zh.ts     # 中文（默认，key 类型来源）
  en.ts     # 英文
```

`common/locales/index.ts` 同理：`export const commonLocales = { zh, en }`，作为 `COMMON` 模块的数据源。

`common/locales/` 用于 common 层基础设施文案（zod、auth 鉴权/权限、file 服务等），其数据最终作为 `COMMON` 模块加载。

新增文案时直接在这两个文件里加 key，**先 zh 再 en**。

#### zh.ts 格式

中文是默认字典和 key 类型来源：

```ts
export const zh = {
  USER_NOT_FOUND: '用户不存在',
  UNAUTHORIZED: '未授权',
} as const
```

#### en.ts 格式

英文必须用 `satisfies I18nLocaleMessages<typeof zh>` 检查 key 完整性：

```ts
import type { I18nLocaleMessages } from '@pika/elysia-plugins'
import type { zh } from './zh'

export const en = {
  USER_NOT_FOUND: 'User not found',
  UNAUTHORIZED: 'Unauthorized',
} satisfies I18nLocaleMessages<typeof zh>
```

#### 新增模块

1. 创建 `src/<moduleName>/locales/{index,zh,en}.ts`（`index.ts` 导出 `export const <moduleName>Locales = { zh, en }`）。
2. 在 `apps/server/common/plugins/i18n.ts` 中追加：
   ```ts
   import { <moduleName>Locales } from '@/<moduleName>/locales'
   ...
   messages: { ..., <MODULE_NAME>: <moduleName>Locales }
   ```
3. 类型推导与运行时会自动覆盖新模块，无需改 `@pika/elysia-plugins`。

### t 的导入

业务代码统一从全局插件导入 `t`：

```ts
import { t } from '@/common/plugins/i18n'
```

调用时使用 `${ModuleName}.${Key}` 形式，模块名使用全大写：

```ts
t('SYSTEM.USER_NOT_FOUND')
t('COMMON.FORBIDDEN')
```

> TS 会在 `t('` 之后列出所有 `MODULE.KEY` 字面量，键入模块名 + `.` 后会进一步过滤到该模块的子 key。

### Key 命名

- 大写下划线，如 `USER_NOT_FOUND`。
- 同业务前缀，如 `CAPTCHA_*`、`VERIFICATION_CODE_*`。
- 描述业务语义，不用中文、状态码或最终文案。
- 语义不同就分开（例如图片验证码用 `CAPTCHA_*`，邮件/短信验证码用 `VERIFICATION_CODE_*`，**不混用**）。

### 变量占位符

`zh.ts` 中用 `{name}` 占位：

```ts
export const zh = {
  PASSWORD_MIN_LENGTH: '密码不能少于{min}个字符',
} as const
```

调用时传参：

```ts
t('SYSTEM.PASSWORD_MIN_LENGTH', { min: 6 })
```

- 参数名只能字母数字下划线，以字母或下划线开头。
- 存在占位符时 params 必填，缺参会触发 TypeScript 错误。
- 所有语言同名 key 必须使用相同占位符。

## 常见使用场景

### 业务错误

用户可见的业务错误用 `HttpError` 配合 `t`：

```ts
import { t } from '@/common/plugins/i18n'
import { HttpError } from '@pika/elysia-plugins'

throw new HttpError(t('SYSTEM.USER_NOT_FOUND'), 404)
```

动态分支用联合类型：

```ts
throw new HttpError(t(usernameIsEmail ? 'SYSTEM.EMAIL_NOT_FOUND' : 'SYSTEM.PHONE_NOT_FOUND'), 401)
```

底层异常只放入 `detail`，面向用户的 `message` 必须走字典：

```ts
throw new HttpError(t('COMMON.FILE_UPLOAD_FAILED'), 400, error.message)
```

禁止硬编码用户可见文案：

```ts
// 错误
throw new HttpError('用户不存在', 404)
```

非用户可见的日志、数据库记录、内部 `Error` 不要求使用 i18n。

### Zod 校验

所有自定义 Zod 校验文案必须使用 `t`：

```ts
const passwordSchema = z
  .string()
  .min(6, t('SYSTEM.PASSWORD_MIN_LENGTH', { min: 6 }))
  .max(30, t('SYSTEM.PASSWORD_MAX_LENGTH', { max: 30 }))
  .refine((value) => isPassword(value), t('SYSTEM.PASSWORD_FORMAT_INVALID'))
```

对象级校验同样用 `t`：

```ts
schema.refine((data) => isValid(data), {
  message: t('SYSTEM.PASSWORD_CHANGE_FIELDS_REQUIRED'),
  path: ['newPassword'],
})
```

### 业务返回内容

接口返回内容不会被i18n处理，当某些场景需要主动发送多语言内容时，需要使用 `i18n.translate` ，例如

```ts
import { i18nPlugin } from '@/common/plugins/i18n'

.use(i18nPlugin)
.get('/demo/hello',({i18n})=>{
  return {
    hello: i18n.translate('DEMO.HELLO'),
  }
})
```

## 请求语言

Web API 请求拦截器会在每次请求时发送当前语言：

```ts
method.config.headers['Accept-Language'] = i18n.global.locale.value
```

请求语言缺失或不受支持时使用默认 `zh`。

## 提交前检查

1. 业务错误使用 `HttpError(t('MODULE.XXX'), status)`。
2. 自定义 Zod 校验文案使用类型化 `t`。
3. 变量文案通过 `{name}` 声明占位符并传入完整 params。
4. 所有语言字典的 key 和占位符与默认语言一致。
5. 没有硬编码用户可见的业务错误文案。
6. 相近概念没有混用 key（如 `CAPTCHA_*` 与 `VERIFICATION_CODE_*`）。
7. 新增 i18n 行为包含默认语言和英文测试。
8. 新增模块时同步在 `common/plugins/i18n.ts` 注册数据源。
9. 执行 `bun lint`、`bun check` 和相关测试。
